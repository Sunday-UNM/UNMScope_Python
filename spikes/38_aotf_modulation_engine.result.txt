CONCLUSIONS
-----------
1. 'AOTF ch Mode' ALONE decides the output. = 2 ("Set AOTF ch") gives the
   DC level; = 0 or 1 gives 0 V. The value of 'AOTF Mode' changed nothing
   in any of the nine cells, so the AOTF **Clock** loop is not consuming
   its register in this bitfile -- consistent with the checked-out FPGA
   top level (HHMI - SPIM FPGA Main VI.vi) instantiating only the AO, AI
   and Shutter loops.
2. The AOTF channel loop's waveform mode is reachable but starves: put in
   Start/Run it outputs 0 forever, because the trigger that should start
   it ('AOTF start trigger' / the 'Start sweep?' global, gated on an
   'AOTF ch FIFO' read) never arrives.
3. The FIFO cannot be loaded from the host: the bitfile declares only
   three DMA channels -- Wvfrm2 (HostToTarget I64), Get Exp, AI data.
4. The AOTF DACs are not reachable through the AO stream either. All eight
   analog outputs are spoken for: AO0 Z Galvo, AO1 X Galvo, AO2 Z Piezo,
   AO4 Dither Galvo, and AO3/AO5/AO6/AO7 = AOTF ch 3/0/1/2. The two
   remaining streamed slots (Tiling, Filter) have no Connector0 AO pin.

=> On THIS bitfile there is no host-side path to a hardware-timed
   modulated AOTF voltage. 'AOTF ch (V)' as a static level is the only
   working path to those DACs. Getting per-line blanking needs either an
   FPGA recompile that wires the AOTF clock loop, or a different physical
   route (DIO9/10/11 carry AOTF ch 4/5/6 as digital lines, and
   DIO6/7/12/14 are ChannelShutter0-3 -- neither investigated).

Side note: the AI scope path is confirmed good for AOTF -- column 19
(AOTF2) read 6308 whenever the register did, so the Waveforms tab can be
trusted on these channels since commit 76ff662 raised the streamed
channel count to 24.
